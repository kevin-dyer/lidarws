STAGE 2: UDP/RTSP TRANSMISSION
─────────────────────────────────────────────────────────────────────────────

Mobile Device broadcasts:
  • UDP 5000: LiDAR frames (struct format: time_us, quality, angle, distances)
  • UDP 5001: IMU samples (struct format: timestamp, ax, ay, az, gx, gy, gz)
  • TCP 5554: RTSP stream (H.264 video encoded)

LATENCY & TIMING
─────────────────────────────────────────────────────────────────────────────

Mobile Device        → Network → Bridge Receiver → Processing → FAST-LIVO2
    |                    |           |              |              |
    0ms                10-20ms      0ms          0ms             30-50ms
    (generation)    (WiFi latency) (decode)   (adapter)       (SLAM algo)

Total end-to-end latency: ~30-80ms (depends on network and WiFi interference)


KEY DESIGN POINTS
─────────────────────────────────────────────────────────────────────────────

1. SEPARATE WORKSPACES
   ├─ lidarws: Your application (mobile bridge + adapter)
   └─ ros2_fast_livo_ws: FAST-LIVO2 (independent SLAM)
   → Easy to develop, debug, and swap components

2. TOPIC ADAPTER (NEW)
   ├─ Minimal: ~10 lines per topic
   ├─ Zero overhead: Direct message passthrough
   └─ Independent: Works with any LiDAR or camera source

3. ROS 2 TOPICS (standard messages)
   ├─ PointCloud2: PCL standard for 3D points
   ├─ Imu: Standard IMU messages with covariance
   └─ Image: Standard sensor image format
   → Any other source can feed FAST-LIVO2 with this setup

4. CONFIGURATION (avia.yaml)
   ├─ Sensor calibration (extrinsic parameters)
   ├─ Preprocessing parameters
   ├─ Algorithm tuning (VIO, LIO options)
   └─ Output options (map density, pose publication)


EXAMPLE DATA RATES
─────────────────────────────────────────────────────────────────────────────

Typical timing during a mapping run:

LiDAR (/livox/lidar):        30-40 Hz × 1000-5000 points/frame
  → ~30-200 MB/s in topics (depends on point count)

IMU (/livox/imu):             20 Hz × 36 bytes/sample
  → ~0.7 KB/s

Camera (/left_camera/image):  20-30 Hz × 640×480×3 bytes (RGB)
  → ~18-27 MB/s in topics

TOTAL NETWORK LOAD: ~50-230 MB/s (high variance)


TROUBLESHOOTING CHECKLIST
─────────────────────────────────────────────────────────────────────────────

✓ Mobile device is on same WiFi network
✓ Mobile IP is correct (e.g., 192.168.1.100)
✓ Both ROS workspaces are sourced
✓ ros2 topic list shows /livox/* topics
✓ ros2 topic hz /livox/lidar returns non-zero
✓ ros2 topic hz /livox/imu ≈ 20 Hz
✓ FAST-LIVO2 node is running (ros2 node list)
✓ RViz2 shows /cloud_pcd topic
✓ No errors in terminal (watch for "node not found", topic subscription issues)
